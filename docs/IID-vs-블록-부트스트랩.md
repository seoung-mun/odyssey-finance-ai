# IID 채택 결정 기록

## 1. 목적

사용자의 과거 월별 유동지출 12~24개월로 미래 소비 경로를 생성할 때 IID bootstrap을
채택한 결정과, 결과가 나쁠 때 재검토할 기준을 정리한다.

내부 계산 API는 `IID_BOOTSTRAP`, 10,000 경로로 확정한다. 블록 방식은 기본 후보가
아니며 rolling-origin 백테스트에서 IID의 coverage나 구간 폭이 나쁠 때만 비교한다.
변경이 필요하면 기획서와 OpenAPI를 먼저 갱신한 뒤 구현한다.

`r_max`는 별도 정책 결정 사항이므로 이 비교 범위에 포함하지 않는다.

## 2. 방식

### 2-1. IID bootstrap

과거의 각 월을 서로 독립인 표본으로 보고 월 단위로 복원추출한다.

```text
과거: [100, 120, 80, 200, 90, 110]
경로: [200, 100, 200, 80, 110, 100]
```

월별 지출의 경험적 분포는 보존하지만 원래 월 사이의 순서와 자기상관은 제거한다.

### 2-2. Block bootstrap

과거 이력에서 겹치는 연속 블록을 만들고 블록 단위로 복원추출해 목표 기간까지
이어붙인다. 마지막 블록이 목표 기간보다 길면 초과분을 자른다.

```text
2개월 블록: [100,120], [120,80], [80,200], [200,90], [90,110]
경로:       [80,200] + [100,120] + [90,110]
```

블록 내부의 단기 연속성과 자기상관은 보존하지만 서로 다른 블록 사이의 연결은 새로
만들어진다.

## 3. 장단점

| 기준 | IID bootstrap | Block bootstrap |
|---|---|---|
| 월별 경험적 분포 | 보존 | 보존 |
| 월간 순서·자기상관 | 제거 | 블록 내부에서 보존 |
| 짧은 이력의 조합 다양성 | 높음 | 블록이 길수록 감소 |
| 총지출 분포 | 자기상관이 있으면 폭과 꼬리를 왜곡할 수 있음 | 자기상관이 있으면 더 현실적일 수 있음 |
| 비현실적인 월 전환 | 발생 가능 | 블록 내부에서는 감소 |
| 파라미터 | 경로 수와 seed | 경로 수, seed, 블록 크기 |
| 구현·검증 | 단순 | 블록 경계와 길이 검증 필요 |
| 계산량 | 작음 | 조금 증가하지만 현재 배열 규모에서는 무시 가능 |
| 달력 계절성 | 보존하지 않음 | 일반 블록만으로는 완전히 보존하지 않음 |

IID가 총지출 분포를 항상 좁히는 것은 아니다. 양의 자기상관을 제거하면 분포가 실제보다
좁아질 수 있고, 음의 자기상관을 제거하면 반대로 넓어질 수 있다. 따라서 방식 선택은
자기상관의 존재만이 아니라 실제 예측 coverage로 판단한다.

## 4. 블록 크기 후보

### 2개월

- 12개월 이력에서도 겹치는 블록 11개를 확보한다.
- 3개월보다 경로 조합이 다양하다.
- 한 달 뒤 반동 소비나 연속 고지출 같은 짧은 관계를 보존한다.
- 첫 비교의 기본 후보로 사용한다.

### 3개월

- 분기 수준의 소비 흐름을 더 오래 보존한다.
- 12개월 이력에서는 겹치는 블록이 10개뿐이고 특정 과거 구간의 반복 영향이 커진다.
- 2개월 방식보다 평가 지표가 명확히 좋아질 때만 채택한다.

단순 블록 방식은 연말·명절처럼 달력 위치에 고정된 계절성을 보장하지 않는다. 사용자당
월별 관측치가 1~2개뿐인 현재 단계에서는 별도의 계절형 bootstrap은 도입하지 않는다.

## 5. 평가 설계

같은 사용자 이력, 같은 평가 구간, 같은 `n_paths`와 seed 집합으로 다음 세 방식을
비교한다.

1. IID bootstrap
2. 2개월 moving block bootstrap
3. 3개월 moving block bootstrap

### 5-1. 데이터 분할

시계열 순서를 유지하는 rolling-origin backtest를 사용한다. 예를 들어 과거 18개월이
있다면 앞 12개월로 다음 1~3개월 분포를 만들고, 실제 다음 소비가 예측 구간에 들어오는지
확인한 뒤 기준 시점을 한 달씩 이동한다. 미래 정보가 학습 구간에 섞이는 무작위 분할은
사용하지 않는다.

### 5-2. 핵심 지표

| 지표 | 계산 | 목적 |
|---|---|---|
| Coverage calibration error | `abs(실제 coverage - 명목 coverage)` | Q70·Q80·Q90 확률의 정확성 |
| 구간 폭 | `Q90 - Q10` 등 | 넓기만 해서 coverage를 맞추는 방식 방지 |
| 총지출 오차 | 실제 누적지출과 예측 중앙값 차이 | 중심 예측의 정확성 |
| 강도 분리도 | 강도별 추천 지출·절감률 간 차이 | 세 계획이 사실상 같아지는지 확인 |
| seed 안정성 | seed별 지표 변동 | 우연한 난수 결과에 대한 민감도 확인 |
| 실행시간 | 요청당 p50·p95 | 500ms 동기 응답 목표 확인 |

Coverage는 구간 폭과 함께 본다. 지나치게 넓은 분포는 coverage만 높이고 사용자에게 쓸모없는
계획을 만들 수 있다. 강도 분리도 역시 크기만 최대화하지 않고 coverage가 정확한 범위에서
비교한다.

## 6. 재검토 기준

IID 백테스트 결과가 나쁠 때 2개월 블록을 첫 대안으로 평가한다. IID보다 coverage calibration error를 일관되게 줄이고,
구간 폭과 seed 안정성이 악화되지 않으며, 강도별 계획 차이가 화면에서 의미 있게 커질 때
블록 방식을 채택한다.

3개월 블록은 2개월보다 같은 지표에서 명확한 개선이 있을 때만 채택한다. 블록 방식이 IID와
비슷하거나 더 나쁘면 구현이 단순하고 짧은 이력에서 조합 다양성이 높은 IID를 유지한다.
