# 개발 로드맵

기준일: 2026-08-26
근거: `docs/QA-결과.md`의 실행 검증, 실제 코드·OpenAPI·SQL

## 현재 상태

계산 엔진과 각 모듈 단위 검사는 녹색이다. 그러나 공개 API 7개가 아직 Spring에 없고,
Spring↔FastAPI·브라우저↔Spring의 자동 실연동 검증이 없다. 다음 웨이브의 목적은 기능을
더하는 것이 아니라 이 경계를 실제로 연결해 녹색 테스트가 배포 가능한 녹색이 되게 하는 것이다.

## 0. 확정된 구현 경계

Google 수동 로그인 1회, profile-gated 자동 E2E 인증, 실행별 PostgreSQL·Redis 격리,
환불 M:N 배분과 미래 환불 예측 제외를 기획서·OpenAPI·SQL 계약으로 확정했다.

## 1. P0 — 계약을 구현과 같게 만들기

완료 조건: 공개 OpenAPI 31개 operation이 controller와 실제 응답까지 대응하고, FastAPI
응답 검증 실패는 500이 아닌 정의된 안전 오류로 끝난다.

- Core: `PATCH /goals/{goalId}`, 예정지출 생성·수정, 재계획 조회·요청·결정·재시도 7개
  operation을 기존 서비스·DB 계약 안에서 구현한다.
- Core: 기존 `CalculationResponseValidator`의 option 3개, band 완전성, simulation·NUMERIC
  검증을 실제 FastAPI HTTP와 DB 저장 경계에서 확인한다.
- Main: OpenAPI와 controller/DTO의 계약 테스트를 추가해 path 또는 필수 field 누락을 CI에서
  실패시킨다.
- Main/Core: M:N 환불 배분 migration과 월 집계를 Spring import/history/응답에 연결한다.
  미래 환불·캐시백은 Analysis 입력에 포함하지 않는다.

## 2. P0 — 실제 서비스 경계 테스트

완료 조건: mock 없이 ephemeral PostgreSQL·Redis·FastAPI·Spring을 연결한 한 사용자 흐름이
자동으로 통과하고, SQL은 실제 PostgreSQL에서 매번 검증된다.

- `test:integration` 레인: Spring이 실제 FastAPI `/internal/simulate`에 요청하고 계획·option·
  band·설명 상태를 DB에 저장한다.
- `test:e2e:real` 레인: 브라우저가 실제 Spring을 거쳐 신규 사용자 → 프로필/목표 → 계획
  생성 → 옵션 선택 → 대시보드를 실행한다. `page.route().fulfill()`은 이 레인에서 금지한다.
- 실패 케이스: FastAPI 401/422/5xx/timeout, Redis 단절, malformed·불완전 계산 응답,
  403/404/409/422/503, 중복 요청, 환불 순액 음수 월.
- DB 레인: SQL `01 → 02 → 05`, KST half-open 월 경계, unique import, 교차 사용자
  예정지출 FK를 일회용 PostgreSQL에서 실행한다.

## 3. P1 — 심사 배포 경계

완료 조건: 선택한 topology에서 HTTPS 로그인 refresh와 API 호출을 실제 브라우저로 한 번
확인하고, 구성값·health check·배포 순서를 재현 가능하게 기록한다.

- Vercel rewrite를 쓰면 API origin, credential/cookie 전달, Google allowed origin을 확인한다.
- Compose로 SPA까지 제공하면 Caddy가 web build와 `/api`를 같은 origin에서 제공한다.
- 실제 Ollama 모델은 staging에서만 품질·p95·RSS를 측정하고, 15초를 넘으면 FALLBACK-only로
  운영한다.

## 4. P1 — 신뢰성·평가

- rolling-origin 백테스트와 coverage 보고서를 고정 fixture·seed·실행 명령으로 남긴다.
- Redis pending reclaim, 중복 delivery, worker 재시작과 장애 격리를 실제 Redis로 검증한다.
- staging에서 계산 p95 ≤ 500 ms, 오류율 < 1%, RSS 지속 증가 없음 기준을 측정한다.
