# 미확정 설계

아래 항목에 의존하는 구현은 건너뛰고 확정 작업을 계속한다. 질문은 작업 웨이브 전후에
묶어서 한다.

| ID | 쟁점 | 근거 | 선택지/권장안 | 영향 | 상태 |
|---|---|---|---|---|---|
| D-001 | AWS 최종 구성 | Qwen 평가 문서 | staging 게이트 후 실시간/전용 fallback 결정 | 인프라·Analysis | 대기 |
| D-002 | 인증 스코프 | 통합 서비스 설계 5절 | Google 로그인과 자체 access/refresh JWT, mock 로그인 없음 | Core·Web | 확정 |
| D-003 | 재계획 임계치 | 사용자·QA 최종 결정 | 단건 `p95×1.15`, 누적 `1.20`, 7·14·21일, 최소 표본 20건 | Core·Analysis | 확정 |
| D-004 | 청년정책 API | 기획서 8절 | 핵심 흐름 뒤로 보류 권장 | Core·Web | 대기 |
| D-005 | 부하 workload | `TODO.md` P5 | 수직 흐름 완료 뒤 staging에서 확정 | 전체 | 대기 |
| D-006 | 샘플 데이터 | 통합 서비스 설계 11절 | 빈 계정 선택형, 결정적 external ID와 사용자별 적재 시각으로 멱등 | DB·Core·Web | 확정 |
| D-007 | 계획 생성 트랜잭션 | 통합 서비스 설계 9절 | FastAPI는 DB 트랜잭션 밖에서 호출하고 계산 결과만 Spring 트랜잭션으로 저장 | Core·Analysis | 확정 |
| D-008 | 샘플 재계획 이력 | 통합 서비스 설계 12절과 현재 `UserServiceImpl` | seed에 재계획 이력을 포함할지 결정; 현재 구현은 프로필·목표·예정지출·거래만 생성 | Core·Web | 대기 |
| D-009 | PostgreSQL image tag | `docs/주의사항.md`와 Compose | 문서는 16.15, 현재 Compose는 16.4이므로 배포 기준 tag 확정 필요 | 인프라 | 대기 |
| D-010 | 재계획 결정 중복 경합 | 공개 API의 `DECISION_ALREADY_MADE`와 현재 Core·DB | 결정 endpoint 구현 시 조건부 update로 1건만 성공시키고 0건은 409로 반환 권장; 전용 DB 제약 추가는 불필요 | Core | 대기 |

결정되면 근거 문서·커밋과 함께 상태를 `확정`으로 바꾼다.
