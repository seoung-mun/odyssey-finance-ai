# 공격 표면 카탈로그

배정 범위에 해당하는 그룹만 읽는다. 각 항목은 "이 조건이면 깨진다" 가설의 씨앗이다.
프레임워크 이름은 여기 없다. 구체적인 파일은 절차 1단계에서 찾는다.

## A. 서비스 내부

**경계값**
- 0, 빈 컬렉션, 단일 원소, 최대값, 음수, null
- 분모가 0이 될 수 있는 나눗셈, 비율 계산
- 첫 항목·마지막 항목만 다르게 처리되는 루프
- 날짜: 월말, 윤년, 자정, timezone 경계, DST

**타입·정밀도**
- 정수 자리에 float가 들어오는 지점, 반올림 방향이 정의됐는지
- 통화·금액 단위 혼용, 문자열과 숫자 사이 왕복 직렬화
- 정밀도가 손실되는 캐스팅, overflow

**상태 전이**
- 상태 머신에서 정의되지 않은 전이를 요청하면?
- 같은 전이를 두 번 요청하면? 되돌리면?
- 중간 상태에서 프로세스가 죽으면 남는 것

**오류 경로**
- catch가 잡는 범위가 의도보다 넓은가. 무관한 오류를 삼키는가
- 실패했는데 로그만 남고 정상 흐름이 계속되는가
- fallback이 명세에 있는 동작인가, 아니면 문제를 숨기는가
- 오류 메시지가 사용자에게 무엇을 하라고 말하는가

**재현성**
- 난수·시간·순회 순서에 의존하는가. seed가 고정되는가
- 같은 입력으로 두 번 돌리면 같은 출력인가

## B. 서비스 경계·통신 — 가장 놓치기 쉬운 그룹

**계약 drift**
- **양쪽 타입 정의를 각각 열어서 필드 단위로 대조한다.** 한쪽만 보면 안 보인다
- 필드명, 타입, nullable 여부, 기본값, 열거형 값 집합
- 명세 문서와 실제 코드가 다른가. 어느 쪽이 진실인가
- 한쪽이 추가한 필드를 다른 쪽이 모르면 무시되는가 거부되는가

**실패 전파**
- 상대가 timeout이면? 5xx면? 4xx면? 연결 자체가 안 되면?
- 각각에서 호출측이 남기는 부분 상태가 있는가
- 재시도가 있는가. 있다면 상대가 멱등한가
- timeout 값이 양쪽에서 일관된가 (호출측 3초, 수신측 10초 작업)

**멱등성·중복**
- 같은 요청을 두 번 보내면 결과가 두 개 생기는가
- 재시도로 인한 중복을 무엇으로 구분하는가
- 네트워크가 끊겨 응답만 유실됐을 때 클라이언트가 뭘 하는가

**동시성**
- 같은 자원에 동시 쓰기. 마지막 쓰기가 이기는가, 충돌을 감지하는가
- 읽고-수정하고-쓰는 구간이 트랜잭션 안인가
- 트랜잭션 안에서 외부 호출을 하는가 (커넥션 점유·롤백 불가)

**인증·신뢰 경계**
- 내부 전용 엔드포인트가 실제로 외부에서 닿는가
- 토큰 만료·회전 시 진행 중이던 요청
- 클라이언트가 보낸 값을 검증 없이 신뢰하는 지점

## C. 명세 ↔ 구현

- 명세에 있는데 코드에 없는 필드·엔드포인트·오류코드
- 코드에 있는데 명세에 없는 동작 (조용히 늘어난 계약)
- 기본값 불일치: 명세의 default와 코드의 default
- 오류 상황에서 명세가 약속한 상태 코드·본문이 실제로 나오는가
- 명세가 "거부한다"고 한 입력이 정말 거부되는가, 조용히 보정되는가
- 문서에 적힌 검증 명령이 실제로 존재하고 통과하는가

## D. 사양 자체

여기서 나온 것은 **판정 불가**이고 owner가 빌더가 아니다.

- 두 문서가 같은 것을 다르게 말한다
- 경계 동작이 어디에도 정의돼 있지 않다 (0일 때? 이력이 부족할 때?)
- 요구가 서로 모순된다 (A를 보장하면서 B도 보장할 수 없다)
- 용어가 문서마다 다른 뜻으로 쓰인다
- "적절히", "합리적으로" 같은 표현이 판정 기준 자리에 있다
- 명세가 불가능한 것을 요구한다 (존재하지 않는 데이터로 계산)

## E. 변경 범위 (diff가 있을 때)

- 작업 지시에 없던 파일이 변경됐다
- 테스트가 검증을 약화시키는 방향으로 수정됐다 (assert 삭제, skip 추가)
- 새로 추가된 코드 경로를 덮는 테스트가 있는가. 기존 테스트가 **변경 전에도 통과했다면**
  이번 변경은 검증되지 않은 것이다
- 주석 처리된 코드, 임시 우회, 하드코딩된 값이 남았다
- 새 의존성이 승인 없이 추가됐다
- 생성 파일·빌드 산출물·비밀값이 커밋에 섞였다
